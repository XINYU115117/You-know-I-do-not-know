llm-lab · 生成流程逻辑图(模型对比 · 可切换)

架构主轴对所有主流大模型相同;可切换的是"能拿到什么 / 拿不到什么 / 有没有思考阶段"。目的:避免"所有大模型都一样"的误解。
① 本地开源 · Qwen2.5-0.5B当前项目 · 手写生成循环
② 云端托管开源 · vLLM/TGI技术方案 §12 备用方案
③ 闭源 API · OpenAI/DeepSeek/Claude可能含 reasoning 模型
所有模型通用(不随切换变化) 真实数据 · 可获取(红线 A) 机制解释(红线 B) 模型内部 · 不可获取(红线 C)
先看结论:主干 1 → 7 对所有 transformer 大模型都一样(都是"逐 token 自回归")。真正不同、也是本图可切换的,只有三点: ① 部署方式决定你能读到什么接口(logits / logprobs / 仅文本); ② 模型类型决定有没有"思考阶段"(reasoning 模型有,普通模型没有); ③ 提供商决定思考文本是否可见。橙色边框 = 通用部分,侧栏与数据标签随视图切换。

4.1
黑盒 · 不可获取(所有模型)
前向传播 model(input, past_key_values) 通用
输入最后 1 个 token + KV cache,一次 forward:embedding → 自注意力 → 前馈 → 输出。本机进程内直接读 logits(generator.py:63-75)。
推理发生在远程服务器;模型与生成循环由 vLLM/TGI 托管,你只能通过其 HTTP 接口取结果,进程内的一切不可见。
完全远程黑盒;没有任何内部状态访问通道。若调用的是 reasoning 模型,可能额外返回一段思考文本(见下)。
思考阶段(仅 reasoning 模型存在):o1 / DeepSeek-R1 / Gemini Thinking 等会先生成一段 reasoning tokens 再作答。 可见性由提供商决定:DeepSeek 返回 reasoning_content 全文 · OpenAI 默认只给摘要 · Anthropic 需显式开启 thinking。 注意:即使看到思考全文,它仍是模型"说出口"的文本,不是内部算法——红线 C 仍然成立。
思考阶段:取决于部署的模型。若在 vLLM 上跑 reasoning 模型(如 QwQ / R1 蒸馏版), 思考 tokens 与作答同流输出,自托管 = 全文可见。但同左:那是输出文本,不是内部状态。
思考阶段:无。Qwen2.5-0.5B-Instruct 是非 reasoning 模型——没有隐藏 thinking channel, 每步 forward 就是全部。"它不在思考,只是在算下一个词的概率"。
  • ✖ 模型"为什么"这样打分(因果归因)
  • ✖ 主观意图 / 想法 / "决定" / 情绪理解
  • ✖ 注意力权重 ≠ "它真正关注什么"(语义归因)
  • ✖ 注意力矩阵 / 隐藏层 / KV cache(服务端内部)
  • ✖ 全词表 logits(仅 logprobs 出口,见 4.2)
  • ✖ 因果归因 / 意图 / 思维链
  • ✖ 全词表 logits / 完整分布 / 任何内部状态
  • ✖ 因果归因 / 意图 / 真实内部思考(思考文本≠内部算法)
  • ✖ 注意力 / 隐藏层 / 缓存
概括:以上属于模型内部算法与训练结果的一部分,任何可视化都不能声称展示它们(红线 C)——这一点三种部署方式完全一致。

4.2
Logits(全词表)out.logits[0,-1] 随部署变化
黑盒唯一出口:全词表(约 15 万维)原始分数,进程内直接读(generator.py:74)。
vLLM/TGI 提供 logprobs 参数,但只返回 top-k 候选的概率(如 top-5),拿不到全词表。
OpenAI 兼容接口可选 top_logprobs(≤20 个);Anthropic 不提供 logprobs。全词表不可能。
✔ 拿得到: 任意 token 的 logit 值(全量)
△ 部分拿得到: top-k 候选的 logprob,无全量
✖ 基本拿不到: 仅少数 API 可选 top-logprobs
▼softmax(logits / temperature)
4.3
全概率分布torch.softmax 随部署变化
所有候选的精确概率,概率和为 1(generator.py:77-78);可再算熵 / top1 / top5 和(不确定度)。
只能从返回的 top-k 概率还原局部;全分布与熵不可算。
仅可选的 top-logprobs 局部概率;无全分布、无熵。
✔ 拿得到: 完整分布 · 熵 / top1 / top5 和(零成本可算)
△ 部分拿得到: 仅 top-k 局部
✖ 不可拿: 无完整分布
▼torch.topk(probs, 5)
4.4
Top-5 候选torch.topk 三种部署都有(级别不同)

由 logprobs 参数提供,与本地等价。
OpenAI 兼容系可选(≤20);Anthropic 无——Top-5 可视化依赖具体 API 能力。
✔ 拿得到: 候选 + 概率 + 名次(已推送 step 事件)
✔ 拿得到: 候选 + 概率 + 名次(经 logprobs)
△ 依 API: OpenAI 系可选 · Anthropic 无
▼top_p 截断 + torch.multinomial
4.5
采样选中multinomial 随部署变化
按概率"抽签",可能选到非第一名甚至不在 Top-5 内(generator.py:84-94);参数本地可控(temperature=0.8, top_p=0.9)。
采样在服务端执行;temperature / top_p 等参数可在请求中设置。
采样在服务端;参数受 API 限制,部分平台不支持自定义 seed。
✔ 拿得到: 选中 token + 精确概率(含 rank=null 情形)
△ 部分拿得到: 选中 token 可见,精确概率受 logprobs 覆盖限制
△ 部分拿得到: 选中文本可见,概率通常不可见
▼拼接 + KV cache 更新

△ 拿得到: 流式输出文本;内部缓存不可见

✔ 拿得到(本地开源 · 最宽)

  • 输入与上下文输入文本 · 对话历史 · 合并上下文 · Token 文本/ID/位置/数量
  • 每步生成全词表 logits · 全概率分布 · Top-5+概率+名次 · 选中 token+精确概率 · 已生成序列 · KV cache
  • 过程与结果逐步耗时(可加)· 总步数 · 总耗时 · 停止原因 · 最终答案
  • 可扩展(零障碍)分布熵/不确定度 · 注意力权重(技术可拿,语义≠归因)

✖ 拿不到(所有模型一致)

  • "为什么选这个"因果归因,不可获取
  • 主观意图 / 想法不可声称
  • 注意力 ≠ 关注数值可读,不等于"看重什么"
  • 训练数据 / 权重先验不可追溯

✔ 拿得到(云端托管 · 中等)

  • 输入与上下文同本地(tokenize 在服务端,结果可读)
  • 每步生成logprobs 的 top-k 候选+概率 · 选中 token · 流式序列
  • 过程与结果usage · finish_reason · 最终答案
  • 拿不到全词表 logits · 全分布 · 熵 · KV cache · 注意力

✖ 拿不到(云端托管)

  • 服务端内部注意力 / 隐藏层 / KV cache
  • 全量数值全词表 logits / 完整分布 / 熵
  • 语义层因果归因 / 意图 / 思维链(与本地一致)

✔ 拿得到(闭源 API · 最窄)

  • 输出最终文本 · 流式增量 · usage · finish_reason
  • 有限 logprobsOpenAI 兼容系可选 top_logprobs(≤20);Anthropic 无
  • 思考文本(如有)DeepSeek reasoning_content 全文 · OpenAI 摘要 · 本地 reasoning 模型则全文可见

✖ 拿不到(闭源 API)

  • 全部内部状态logits / 分布 / 注意力 / 缓存 / 隐藏层
  • 真实内部思考思考文本 ≠ 内部算法,仍是输出文本
  • 语义层因果归因 / 意图(与本地一致)

◆ 三层边界(交互设计依据)

真实数据层:黑盒出口之后的全部数值 —— 范围随部署方式伸缩,交互只能基于当前视图的数据。

机制解释层:帮助理解的动画与标注,必须带"机制解释"标记。

不可获取层:黑盒内部与因果,所有模型一致 —— 显式标注"模型内部算法的一部分,不可查看"。
