## 1. 推荐开源模型（满足 Token 级 Logits 访问）

**首选：Qwen2.5-0.5B-Instruct**

事实依据：
- 官方开源权重（Apache 2.0），HuggingFace 可下载（已实测连通）；
- 基于 BPE tokenizer，**中文 token 效率高**（多数单字 = 1 token），适合中文问答产品；
- `transformers` 中 `model(input_ids)` 直接返回全部位置 logits，`softmax → topk` 即可得到 Top-5 与概率，**无任何访问障碍**；
- 权重约 1GB（BF16），本机内存峰值约 2–3GB，16GB 完全够。

备选对比（均为实测可达的开源模型）：
| 模型 | 中文质量 | CPU 速度(估) | 体积 | 结论 |
|---|---|---|---|---|
| Qwen2.5-0.5B-Instruct | 好 | 10–25 token/s | ~1GB | **推荐** |
| Qwen2.5-1.5B-Instruct | 更好 | 3–8 token/s | ~3GB | 备选，速度煎熬 |
| Llama-3.2-1B/3B | 一般 | 慢 | 2–6GB | 中文弱，不选 |
| GPT-2 | 差 | 快 | ~0.5GB | 中文 token 浪费严重，不选 |

## 2. 预计算力要求

- 推理：纯 CPU（12 核 Intel），无需 GPU；单步 forward 约 40–100ms → 逐 token 可视化节奏天然合适（太快看不清、太慢等不起）。
- 内存：峰值约 2–3GB（16GB 充裕）。
- 磁盘：模型下载约 1GB，缓存于 `data/`。
- 首次启动：加载 tokenizer + 模型约 10–30 秒，之后常驻内存、请求间复用。

## 3. MVP 最终模型

**Qwen2.5-0.5B-Instruct**，本地 CPU 推理。输出长度由 `max_new_tokens=200` 兜底，满足 80–150 中文字目标。

## 4. 前端技术选型

**纯 HTML + CSS + 原生 JS，零构建工具。**

理由：
- 本机无 node/npm，零构建 = 浏览器直接打开即用，vibe coding 最友好；
- 无框架依赖，单文件 `app.js` 管状态机 + SSE 客户端 + 渲染；
- 可视化用 CSS 动画 + 少量手写 SVG（概率条、Token 卡片），不引第三方库；
- 未来如需工程化，可无损迁移到 Vite（文件结构不变）。

## 5. 后端技术选型

- **Python 3.9 + FastAPI + uvicorn**（ASGI，原生支持 SSE）；
- **transformers + torch(CPU)**：加载模型、tokenizer、自定义生成循环；
- `requirements.txt` 固定版本（torch 2.6.x 兼容 py3.9；transformers 取兼容 3.9 的版本）；
- 会话状态存内存 dict（MVP 单机够用），`conversation_id` 为键。

## 6. 模型服务架构

单进程常驻：启动时加载模型为全局单例，每个 SSE 请求复用。

**手写生成循环**（核心，伪代码）：
```python
input_ids = tokenizer(full_context)["input_ids"]   # 输入 + 历史合并
while len(generated) < max_new_tokens:
    logits = model(torch.tensor([input_ids])).logits[0, -1]  # 最后一位
    probs  = softmax(logits)
    top5   = topk(probs, 5)                    # 真实 Top-5 及概率
    chosen = sample(probs, temperature, top_p) # 实际采样
    yield build_step_event(step, top5, chosen)
    input_ids.append(chosen)
```
- 不用 `model.generate()` 主流程（虽然 `output_scores=True` 也能拿 logits，手写循环更直接可控、易加 step 事件）；
- 停止条件：EOS 或 max_new_tokens，可配置。

## 7. 生成步骤流式传输架构

- **SSE**（Server-Sent Events）：`StreamingResponse(media_type="text/event-stream")`；
- 单向服务端推送，完全满足"用户只观看"（比 WebSocket 简单，无需双向）；
- 事件类型四类：`meta`（开始，含上下文与输入 token）→ `step`×N（每步）→ `done`（结束）｜ `error`（任意时刻中断）；
- 心跳：本地服务几乎不需要，预留注释行 `: ping` 方案；
- 断线：后端检测到客户端断开即中止生成循环（省算力），前端提示可重试。

## 8. 前后端数据协议（精确 Schema）

字段名**锁定**，前端渲染与后端生成共用此契约，改字段需同时改两端 + 本文档。

### 8.1 `meta` 事件（会话开始）
```json
{
  "event": "meta",
  "data": {
    "conversation_id": "c_001",
    "model": "Qwen2.5-0.5B-Instruct",
    "input_text": "为什么天空是蓝色的",
    "history_rounds": 0,
    "input_tokens": [
      { "token_id": 100678, "token_text": "为什么", "position": 0 },
      { "token_id": 101916, "token_text": "天空", "position": 1 }
    ],
    "context_token_count": 48,
    "history_token_count": 0
  }
}
```
- `input_tokens`：**仅当前输入**的 token（不含历史、系统提示、chat 模板标记）；
- `context_token_count`：完整上下文（系统 + 历史 + 当前输入 + 模板）的 token 数；
- `history_token_count`：历史 + 系统部分 token 数，前端据此把历史渲染为折叠块；
- 上下文瘦身：后端只保留最近 3 轮对话（`MAX_TURNS=3`），更早轮次不再参与计算。

### 8.2 `step` 事件（每生成一步一条）
```json
{
  "event": "step",
  "data": {
    "step": 1,
    "context_token_count": 48,
    "generated_text_so_far": "因为",
    "candidates": [
      { "token_id": 11,   "token_text": "，", "probability": 0.31, "rank": 1 },
      { "token_id": 505,  "token_text": "再", "probability": 0.22, "rank": 2 },
      { "token_id": 388,  "token_text": "而", "probability": 0.16, "rank": 3 },
      { "token_id": 449,  "token_text": "它", "probability": 0.10, "rank": 4 },
      { "token_id": 100,  "token_text": "然后", "probability": 0.07, "rank": 5 }
    ],
    "selected_token": { "token_id": 11, "token_text": "，", "probability": 0.31, "rank": 1 }
  }
}
```

### 8.3 `done` 事件
```json
{
  "event": "done",
  "data": {
    "final_answer": "因为……",
    "total_steps": 42,
    "duration_ms": 8532,
    "stop_reason": "eos | max_tokens"
  }
}
```

### 8.4 `error` 事件
```json
{
  "event": "error",
  "data": { "code": "INPUT_TOO_LONG", "message": "输入不能超过 100 个中文字符" }
}
```
错误码清单（MVP）：`INPUT_TOO_LONG` / `CONTEXT_TOO_LONG` / `MODEL_UNAVAILABLE` / `INTERNAL`。

> 前端将 `step.data.candidates` 与 `selected_token` 直接渲染为"候选区 + 概率条 + 选中高亮"；`token_text` 是逐字节真实 tokenizer 输出，前端**不得改写**。

| **M4 打磨** | 动效节奏、空/错误/加载态、信息层级 | 用户测试可读性 |

## 11. 技术风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| Python 3.9 与 torch 新版不兼容 | 中 | 固定 torch 2.6.x + 兼容版 transformers；必要时 Homebrew 装 Python 3.11 |
| CPU 生成慢（尤其长答案） | 中 | 0.5B + max 200 token 上限；过程面板有进度感 |
| 首次模型下载失败/慢 | 低 | HuggingFace 镜像（HF_ENDPOINT）；下载后缓存 data/ |
| SSE 断线 | 低 | 后端 abort 节省算力；前端提示重试 |
| 长对话上下文超限 | 低 | 每轮检查 token 数，超限提示开新会话 |
| token 文本含换行/特殊字符 | 低 | 前端渲染用转义，token 展示保持原样 |

## 12. 备用方案（本地托管成本过高时）

1. **云端 GPU 自建推理**：部署 vLLM 或 TGI（两者均支持 `logprobs` 返回真实 logits），跑 Qwen2.5-7B；**SSE 协议与前端零改动**，仅后端换推理客户端；
2. **升级本机模型**：换 Qwen2.5-1.5B，仅改模型路径与生成参数；
3. **模型下载加速**：HF 国内镜像 / 预下载打包。

## 13. 垂直切片原型方案（M0，无 UI）

`scripts/verify_slice.py` 执行：
1. 加载 tokenizer + 模型；
2. 输入固定问题（如"为什么天空是蓝色的？"）；
3. 打印 `input_tokens`（token 文本 + ID，来自真实 tokenizer）；
4. 手写循环生成 ≤10 步，每步打印 top-5（token 文本/ID/概率）与选中 token；
5. 打印最终答案与停止原因。

**通过标准**（数据链路真实性验证，PRD F4–F6 的先导）：
- 每步 5 个候选概率和 ≈ 1（softmax 归一化）；
- 选中 token 必然在 top-5 候选内且概率一致；
- token 文本为真实 tokenizer 输出，无伪造。
通过后才进入 M1 界面开发。
