# PRD v1 — 交互式 AI 模型机制体验网站

> 事实来源：`docs/01-产品原始定义-v1.0.md`（Codex 交接文档，本 PRD 不重复其全文，只固话决策与工程化）

---

## 1. 产品一句话

一个让不懂 AI 的用户**亲眼看到**语言模型如何把问题变成逐 Token 的答案的网页体验——机制教育产品，不是聊天工具，不是科普文章。

## 2. 核心目的

- 让用户理解：文本如何被切分、答案如何逐 Token 生成、每一步为何存在多个可能方向、模型为何可能与预期不符。
- 反目标：不让用户误以为模型像人一样"先想好再回答"。

## 3. 目标用户

用过聊天 AI、不了解模型工作流、容易把模型输出理解为人类式推理的普通用户。

---

## 4. 产品红线（不可违反）

| # | 红线 | 落地要求 |
|---|---|---|
| 1 | **真实性** | 每个视觉元素必须属于三类之一：真实数据 / 机制解释 / 不可获取内容 |
| 2 | **可区分** | 界面上真实数据与机制解释必须可明确区分（标记/样式/分区，具体形式见视觉规范） |
| 3 | **禁止伪造** | 不展示伪造概率、编造候选 Token、伪思维链、主观意图声称 |
| 4 | **过程即产品** | 生成过程是主要体验，不允许为了出答案而压缩或跳过可视化 |
| 5 | **不干预** | 用户只能观看，不能暂停、回退、选择 Token、改参数 |

## 5. 已确认决策（评审拍板）

| 维度 | 决策 |
|---|---|
| 模型 | **Qwen2.5-0.5B-Instruct，本机 CPU 推理**（满足：真实 Tokenizer、Token ID、每步 Logits、生成参数可控） |
| 运行环境 | 本机 Intel Mac（12 核 / 16GB），无需 GPU |（后续需要部署网站）
| 视觉方向 | **数据实验室风**：深色面板 + Token 卡片 + 概率条 + 步骤编号 |（后面确定了视觉风格我要改）
| 历史对话呈现 | 早期轮次**折叠为"历史上下文"模块**，最新一轮完整展开 |
| 生成参数 | temperature≈0.8、top_p≈0.9、max_new_tokens≈200、停止条件可配置 |
| 前后端 | Python + FastAPI（后端）/ 纯 HTML/CSS/JS 零构建（前端） |
| 通信 | SSE 流式推送结构化生成事件 |

> 历史遗留：曾考虑 DeepSeek API，因不暴露 Logits 违反红线 1/3，已否决（记录于决策日志）。

## 6. MVP 范围

**包含**：仅文字多轮问答；≤100 中文字输入；80–150 字输出；真实 Tokenization；真实 Token ID；逐 Token 生成；每步真实 Top-5 候选与概率；真实选中 Token；最终答案；后续轮次使用对话历史。

**不包含**：图像生成/上传/理解、Embedding、语义搜索、RAG、联网、工具调用、Agent、用户选择候选、用户改生成参数、思维链展示、主观思考声称、最终隐喻世界（视觉后置）。

## 7. 用户流程与状态机

```
IDLE → SUBMITTING（校验发送）→ TOKENIZING（输入+历史合并后 Tokenization）
→ GENERATING（逐步 Top-5 候选/概率/选中 → SSE 推送 → 可视化）
→ COMPLETING → ANSWER_READY →（可下一轮）→ IDLE
                    ↘ ERROR（可恢复）
```

状态迁移规则：仅当 `GENERATING` 全部步骤展示完成，才进入 `ANSWER_READY`；`ANSWER_READY` 前禁止提前展示最终答案。

## 8. 三层产品模型（照搬原始定义，作为数据契约）

| 层 | 内容 |
|---|---|
| 模型流程层 | 接收上下文 → Tokenization → 上下文计算 → 下一 Token 分布 → Top-5 提取 → Token 选择 → 更新上下文 → 重复 → 完成 |
| 真实数据层 | 用户输入、对话历史、合并上下文、Token 文本/ID、步骤号、Top-5 候选、候选概率、选中 Token 及其概率、已生成序列、最终答案 |
| 可视化层 | 句子进入 → Token 块拆分 → 关系/影响结构变化 → 候选出现 → 概率可见 → 选中高亮 → 答案逐 Token 增长 → 最终答案入聊天记录 |

## 9. 多轮对话逻辑

- 每轮新问题：历史消息 + 当前输入合并 → Tokenization → 基于完整上下文生成。
- 视觉呈现（已确认）：早期轮次折叠为"历史上下文"模块（显示轮数 + 占用的 token 数），最新一轮完整展开。
- 架构要求：可视化层必须保留"未来把历史全部展开为 Token 序列"的扩展位，不因当前折叠决策写死。

## 10. 输入输出限制

- 输入：仅文字，≤100 个中文字符（前后端双重校验）。
- 输出：目标 80–150 中文字；`max_new_tokens` 兜底强制停止；停止条件（结束符/EOS）可配置。
- 生成长度受控是硬要求（逐 Token 可视化时长与输出长度成正比，过长体验不可接受）。

## 11. 数据协议（与原始定义 11 章一致，字段名锁定）

`Turn / TokenData / GenerationStep / CandidateToken / Conversation` 结构照原始定义 11 章，**字段名不允许后端前端各自发挥**，详细 JSON Schema 与事件流见《技术方案 v1》第 8 节。

## 12. MVP 验收标准（可执行版）

### 12.1 功能验收
| # | 验收项 | 检查方法 |
|---|---|---|
| F1 | 可提交文字问题 | 界面操作 |
| F2 | 输入长度校验 | 超 100 字提交被拦截，前后端各一次 |
| F3 | 多轮对话 | 连续两轮问答成功，第二轮上下文含第一轮 |
| F4 | 真实 Tokenizer 输出 | 前端展示的 token 文本/ID 与 `transformers` tokenizer 输出**逐字节一致** |
| F5 | 每步 Top-5 真实 | 与当步 `softmax(logits)` 最大 5 项一致，概率和为归一化结果 |
| F6 | 选中 Token 真实 | `selected_token` 等于实际采样结果，且出现在 candidates 中 |
| F7 | 逐 Token 生成 | SSE 事件步数与生成步数一致，无跳步无合并 |
| F8 | 输出长度受控 | 生成停止于 EOS 或 max_new_tokens |
| F9 | 过程先于答案 | 答案仅在全部步骤展示后出现 |

### 12.2 真实性验收
- 不展示伪造概率 / 编造候选 / 伪思维链（F4–F6 保证数据源真实）。
- 真实数据与机制解释视觉可区分（红线 2，视觉阶段检查）。

### 12.3 UX 验收
- 用户能看清：输入如何变 Token、多个候选、哪个被选中、答案逐 Token 增长、过程视图与最终答案的区分、可进入下一轮。

## 13. 非 MVP 扩展（仅记录，不实现）

Embedding/语义相似度、RAG、图像生成、图像理解、用户控制生成（Temperature/Top-p/Seed/候选选择/重跑/路径对比/模型对比）。扩展需真实数据可达性论证，沿用三层模型与红线。

## 14. 未决事项（后置，不阻塞开发）

- 视觉规范细节（信息层级、动效节奏、真实/解释标记的具体样式）——视觉阶段定。
- 最终隐喻世界——明确排除在 MVP 外。
- 对话历史"折叠 vs 展开"的最终视觉表现——先按折叠实现，架构留扩展位。
